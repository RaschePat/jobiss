# Design Anti-patterns v0.1

These are recurring failure modes, not a list of forbidden visual styles. A pattern is a problem only when it appears without a product-specific reason or harms the intended result.

## A-01 Generic SaaS Assembly
Predictable hero + CTA + repeated rounded cards + feature grid used because it is familiar rather than because it expresses the product.

## A-02 Safe Average Aesthetic
Pastel color, soft radius, mild shadow, gradient, and generic illustration combined into a universally agreeable but indistinct result.

## A-03 Decorative Metaphor
Blobs, glows, floating shapes, icons, envelopes, or other metaphors added only to fill space rather than support meaning, hierarchy, or interaction.

## A-04 Uniform Visual Weight
Every section receives similar size, spacing, contrast, and component treatment, leaving no deliberate hierarchy. This can be valid only when a deliberately flat or exploratory experience is part of the intent.

## A-05 Style Before Structure
Visual decoration is developed before the information hierarchy and core user action are understood.

## A-06 Reference Mimicry
Copying the visible surface of a reference instead of extracting and adapting the underlying design principle.

## A-07 Unjustified Rule Breaking
Calling an accidental usability or composition problem “intentional” after the fact. A meaningful deviation should connect to pre-defined intent, create an observable benefit, and justify its cost.

## A-08 Over-correction for Usability
Removing tension, discovery, asymmetry, density, or expressive choices solely because a generic UX convention favors maximum immediate clarity.

## A-09 Portfolio-Only Surface
A visually dramatic screen that does not plausibly support the real product flow or required actions.

## A-10 AI Ornament Creep
Repeated use of generic AI visual symbols, sparkles, glowing gradients, abstract orbs, excessive badges, and decorative micro-elements that make the interface feel machine-generated rather than product-specific.

## Update Rule
Add a new anti-pattern only when it is repeated, high impact, repeatedly corrected by the user, independently identified in evaluation, or persistently harms the project. Do not expand this library merely to encode personal taste.
