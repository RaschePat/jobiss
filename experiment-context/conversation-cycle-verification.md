# 대화 사이클 구현·검증 기록 · 2026-10-07

목표: 사용자의 경험을 AI가 해석하고, 사용자가 대화로 고치며 직무 가능성을 탐색하는 과정을 실제로 동작하게 만들고 검증한다.

검증에 쓴 입력:

> 조경학과에서 공원 설계를 했고, 컴퓨터공학과로 옮겨 팀 프로젝트에서 아이디어를 내고 기획안을 정리하는 역할을 맡았어요. 글 쓰는 걸 오래 좋아했습니다.

## 1. 무엇을 바꿨나

### 근거 없는 출력 제거
- `POST /api/ai/match-report` 삭제. 키가 없을 때 `matchScore: 92`를 하드코딩해 반환했고, 입력과 무관한 문장("꾸준한 자기주도적 실행력이 돋보여요")을 만들었다. 프롬프트도 "75–96 사이 점수"를 요구했다. 클라이언트에서 호출하지 않는 코드였다.
- `POST /api/ai/tune-hypothesis` 삭제. 아무것도 계산하지 않으면서 "정확도를 높였습니다"라고 응답했다.
- 시드 데이터에서 `initialUserProfile`, `initialJobHypotheses`(점수 92/84/78/74 포함), `initialNotifications`를 삭제하고 체험 공고의 `matchScore`를 제거했다. 데이터 모델에서 `confidenceScore`, `matchedJobsCount`, `matchScore` 필드를 없앴다.

### 데이터 모델 — 근거와 해석의 분리
`src/types.ts`

| 타입 | 역할 |
|---|---|
| `EvidenceSpan` | 사용자 문장에서 그대로 잘라낸 조각. 원문에 반드시 존재 |
| `JobHypothesis.evidenceIds` | 가설을 뒷받침하는 근거. 비면 근거 없는 가설 |
| `JobHypothesis.interpretation` | 해석. 근거와 별도 필드 |
| `JobHypothesis.status` | `supported` / `tentative` / `insufficient` |
| `ClarifyingQuestion` | 확인 질문과 그 질문이 필요한 이유(`why`) |
| `ConversationTurn` | 사용자의 답변 또는 정정 |
| `AnalysisResult.withheld` | 판단 보류 사유 |

### 인용 검증 — 모델이 지어낸 근거를 막는 장치
`src/grounding.ts`의 `locateQuote`와 `sanitizeModelOutput`.

1. 모델이 돌려준 인용을 사용자 원문(경험 + 고른 관심 + 대화 중 사용자가 쓴 말)과 대조한다. 공백 차이만 허용한다.
2. 대조에 실패한 인용은 버린다. 화면에 나가는 인용은 원문에서 잘라낸 문자열이다.
3. 확인된 근거가 하나도 없는 가설은 내보내지 않는다.
4. 가설이 하나도 남지 않으면 판단 보류로 처리한다.
5. 허용되지 않은 status 값은 `tentative`로 내린다.

서버에서 분리한 이유: `server.ts`는 import하면 서버가 뜨기 때문에 테스트할 수 없었다. 순수 함수로 빼서 Gemini 응답을 흉내 낸 입력으로 검증한다.

### 체험 모드 (API 키 없음) — 키워드 목록 제거
이전에는 8개 관심마다 키워드 목록을 두고 부분 문자열로 매칭했다. 이번에 **키워드 목록을 삭제했다.**

- 사용자 문장을 구두점 기준으로 잘라 **근거로만** 보여준다. 의미는 해석하지 않는다.
- 직무 가설은 사용자가 **직접 고른 관심에서만** 만든다. 추론이 아니라 사용자의 선택이기 때문이다.
- 고른 관심이 없으면 가설을 만들지 않고 판단을 보류한다.
- 근거 조각마다 "가장 재미있었던 부분"을 묻는 확인 질문을 만든다.
- 정정한 가설은 제외하고, 답변·정정 문장은 사용자가 쓴 말이므로 새 근거가 된다.

### AI 모드 (Gemini)
프롬프트에 다음을 명시했다. 인용은 원문에서 글자 그대로 복사할 것, 사용자가 말하지 않은 경험을 만들지 말 것, 해석과 근거를 구분할 것, 모호하면 질문할 것, 근거가 부족하면 보류할 것, 사용자 정정을 반드시 반영할 것, 점수·퍼센트를 만들지 말 것. 응답은 위 인용 검증을 거친다.

모델명은 `GEMINI_MODEL` 환경변수로 바꿀 수 있다.

### 화면
- 가설 카드: **"내가 쓴 문장에서"**(원문 인용)와 **"AI가 읽은 내용"**(체험 모드에선 "이렇게 이어봤어요")을 나눠 보여준다. 근거 강도 배지.
- **"이 해석은 달라요"** → 무엇이 다른지 입력 → 정정 반영 후 재분석.
- **"조금 더 알고 싶은 게 있어요"** → 질문마다 이유와 답변 입력 → 재분석. 답한 질문은 목록에서 빠진다.
- **"내가 더 들려준 이야기"** → 지금까지의 답변·정정 목록. ×로 빼면 그 상태로 재분석.
- 근거가 없을 때 제목이 "가능성을 찾았어요"가 아니라 **"단정하기 전에, 조금 더 들려주세요"**로 바뀐다.
- 상단에 **"체험 모드 — AI 미연결"** / **"AI가 찾아본 연결"**을 표시한다. `/api/health`가 `analysisMode`를 돌려준다.
- 편지 미리보기가 정정을 반영한다. 사용자가 거절한 직무를 계속 권하지 않는다.

## 5. 남은 한계

1. **실제 Gemini 호출을 검증하지 못했다.** 이 환경에 `GEMINI_API_KEY`가 없다. 응답 후처리는 모의 응답으로 테스트했지만, 실제 모델이 인용을 글자 그대로 복사하는지, 질문의 질이 어떤지, 정정을 실제로 반영하는지는 확인하지 않았다. 모델명 `gemini-3.7-flash`가 유효한지도 확인하지 않았다. **포트폴리오로 내보내기 전에 키를 넣고 이 문서의 입력으로 반드시 한 번 돌려봐야 한다.**
2. **체험 모드는 문장을 해석하지 않는다.** 의도한 설계다. 그래서 체험 모드에서 "조경학과 + 글쓰기 → 기획자" 같은 연결은 나오지 않고, 답변을 해도 가설이 새로 생기지 않는다. 해석은 AI 모드에서만 일어난다.
3. **체험 모드의 정정은 '제거'만 한다.** 해석을 고쳐 쓰지 못한다.
4. **문장 분리는 구두점 기준이다.** 쉼표 없이 길게 이어진 문장은 하나의 큰 근거가 되고, 4자 미만 조각은 버린다.
5. **인용 검증은 공백 차이만 허용한다.** 모델이 쉼표 하나를 빼고 인용해도 버려진다. 잘못된 근거가 나가는 방향이 아니라 맞는 근거를 놓치는 방향의 오류다.
6. 정정 문장도 근거 목록에서는 `answer`로 분류된다.
7. **답변·정정마다 전체 재분석을 호출한다.** AI 모드에서는 호출 비용이 대화 길이에 비례한다.
8. **분석 엔드포인트에 호출 제한이 없다.** 키를 넣고 공개 배포하면 누구나 할당량을 쓸 수 있다. 배포 전에 제한이 필요하다.
9. 저장 형식이 v1에서 v2로 바뀌어, 이전에 진행하던 브라우저 상태는 처음부터 시작된다.
10. 랜딩(`/`)의 "잘 맞는 이유부터", "추천" 문구는 이번 범위가 아니라 그대로다.
11. 채용 API 연동은 범위에서 제외했다. 우편함은 여전히 체험 공고다.
