# Jobiss Brief v0.5 — Common Input

기획의 기준 문서는 [`product-plan.md`](product-plan.md)다. 이 파일은 그 기획을 디자인 작업용으로 압축한 것이다. 충돌하면 `product-plan.md`를 따른다.

## Product
Jobiss(잡이쓰)는 사용자가 자기 맥락을 아는 상대와 대화하며 직무 가능성을 발견하고, 그 발견이 쌓이고, 관련 공고가 도착하고, 자신이 무엇을 만족하는지 알게 되는 커리어 서비스다.

두 가지가 함께 있어야 성립한다.

- **쌓이는 프로필** — 매번 처음부터 자신을 설명하지 않아도 되게 하는 기억. 분류용이 아니라 대화 상대의 기억이므로 **사용자가 열어보고 고칠 수 있어야 한다.**
- **도착하는 공고** — 사용자가 구인 사이트를 뒤지고 공고를 복붙해 "이거 나랑 어울려?"라고 묻던 반복 노동의 자동화. 은유가 아니라 실제 작업의 대체다.

## Problem
사용자는 자신이 어떤 직무와 맞는지, 지금까지의 경험을 어떻게 연결해야 하는지, 무엇이 부족하고 다음에 무엇을 준비해야 하는지 판단하기 어렵다.

경험은 흩어진 채로 남아 있고, 지원할 때마다 매번 처음부터 다시 설명된다.

## Core Flow
1. 입력 — 관심이나 경험 하나로 시작할 수 있다
2. 대화 — 판정하지 않고 주고받으며 가능성을 발견한다. 결론을 던지는 추천이 아니다
3. 축적 — 발견과 맥락이 프로필로 쌓이고, 사용자가 열어보고 고칠 수 있다
4. 도착 — 프로필로 걸러진 공고가 매일 온다 (1층)
5. 대조 — 관심 공고를 열면 본문과 프로필을 대조해 만족하는 것·부족한 것·다음 준비를 낸다 (2층)
6. 피드백 — 선택과 새 경험이 다시 프로필로 돌아간다

## Main Features
- **Profile** — 쌓이는 기억. 분류표가 아니라 대화 상대의 맥락이며, 열람과 수정이 가능해야 한다
- **Discovery Conversation** — 흩어진 경험을 다르게 엮어 몰랐던 직무 가능성을 찾는 대화
- **Job Mailbox** — 매일 도착하는 공고 (1층). 손으로 뒤지던 탐색의 대체
- **Job Fit Report** — 공고 본문과 프로필 대조 (2층). 복붙하며 묻던 일의 대체
- **Next Action** — 부족한 것을 어떻게 채울지

## 2층 구조
채용 API는 **자격요건·주요업무의 문장을 주지 않는다.** 대신 경력 조건(신입 여부와 요구 연차), 학력, 직무 코드, 공고 키워드 배열, 연봉·지역·마감을 준다. 본문은 읽을 수 없지만 **키워드 검색으로 탐침할 수는 있다.** 그래서 깊이를 층으로 나눈다.

- **1층 (매일 자동 도착)** — 걸러서 배송하고, 도착 이유는 확정적으로 아는 것만 말한다. "신입 지원 가능"이라는 사실 하나가 "지금 지원해도 된다"는 신호가 되므로 얕아도 가치가 있다.
- **2층 (열었을 때)** — 경력·학력처럼 확정 판단이 되는 것과, 키워드 겹침·본문 탐침처럼 정황 근거인 것을 **구분해서** 제시하고 다음 준비로 잇는다.

아는 것과 짐작하는 것을 섞어 말하면 그게 환각이다. 층마다, 항목마다 말할 수 있는 범위를 지킨다.

공고는 보유하지 않고 **표준 URL로 사람인에 연동한다.** 사람인 API 약관상 유료화·재판매가 금지되므로 비상업으로 운영한다. 호출은 1일 500회 제한이다.

## 기존 서비스와 갈라지는 지점
"왜 이 공고가 맞는지" 설명하는 글은 LLM으로 누구나 만들 수 있어 그 자체로는 방어력이 없다. 잡이쓰가 다른 지점은 다음과 같다.

- **이력 기반 추천이 아니다.** 학과와 자격증으로 미래를 좁히면 사용자를 원래 자리로 되민다. 같은 재료를 **다르게 배열해 보여주는 쪽**이어야 한다.
- **범용 AI와 달리 기억이 쌓이고, 그 기억을 사용자가 열어보고 고칠 수 있다.** 범용 AI는 흘러가듯 한 말에 꽂혀도 사용자가 알 수 없다.
- **발견에서 끝나지 않고 실제 공고와 다음 행동으로 이어진다.**

근거는 사용자가 실제로 제공한 입력에서만 나와야 한다. 지어낸 근거 한 건이 제품 약속 전체를 무너뜨린다.

## Target User
- 취업 방향을 탐색 중인 구직자
- 자신의 경험을 직무/공고와 연결하기 어려운 사용자

## Open Questions — 아직 결정하지 않음
가장 큰 것은 **2층 본문을 어떻게 확보할지**다. 이게 안 풀리면 적합도 리포트가 성립하지 않는다.

베타 대상, 수익 구조와 기관 채널, Score vs Evidence도 미결이다. 전체 목록과 배경은 [`product-plan.md` 9절](product-plan.md)에 있다.

여기 적혀 있다고 채택된 것도, 빠져 있다고 배제된 것도 아니다.

따라서 이 브랜치에는 랜딩 디자인이 따라야 할 기존 화면이 없다.

남아 있는 `src/data`, `src/types.ts`, 서버 로직과 `experiment-context/functional-map.md`는 **제품 기능과 데이터/행동 구조를 이해하기 위한 근거**다.

과거 모바일 UI를 Git history에서 복구하거나 재구성할 필요가 없다.

**"기존 기능 유지"는 제품의 핵심 capability와 사용자 흐름을 보존하라는 의미이며, 과거 UI 형식이나 화면 목업을 복원하라는 의미가 아니다.**
