# Design Skill v0.1

## Trigger
Use this workflow for requests to design, redesign, or materially improve a website, landing page, app, or digital interface.

## Inputs
- User request
- Relevant project context
- Existing brand facts/assets/constraints
- Design evaluation standard
- Design anti-pattern library

## Workflow

### 1. Understand
Identify the product problem, primary user, page purpose, primary action, required functions, known brand facts, and implementation constraints. Infer minimally when context is sufficient.

### 2. Define Design Intent
Before choosing visual components, define internally:
- Primary User
- Primary Goal
- Primary Action
- Core Message
- Experience Priority on a Utility ↔ Expression spectrum
- Desired Feeling

### 3. Research References when useful
If reference research would materially improve the result and tools allow it, research relevant examples. Analyze principles rather than copying surfaces: information hierarchy, typography, composition, density, navigation, CTA treatment, motion, brand expression, and distinctive devices.

### 4. Commit to a Visual Thesis
Choose one clear visual argument that connects the product meaning to the interface. Avoid generic theses such as “clean, modern, professional.” The thesis should explain why this product should look and feel this way.

### 5. Establish the Visual System
Make deliberate decisions about:
- Information architecture and hierarchy
- Typography
- Grid and composition
- Spacing and density
- Color
- Components
- Imagery/illustration when appropriate
- Motion when appropriate
- Background and depth

Do not default automatically to rounded cards, generic gradients, centered hero sections, or familiar SaaS assembly patterns.

### 6. Implement
Produce a functional result. Preserve the design intent through implementation rather than reducing it to the easiest component structure. Maintain basic responsive usability and avoid breaking existing required functionality.

### 7. Render and Inspect
Inspect the actual rendered interface, not code alone. Check first-gaze hierarchy, typography, composition, rhythm, spacing, clipping/overflow, responsive behavior, and whether the visual thesis is perceptible.

### 8. Evaluate
Use `standards/design-evaluation.md`.

### 9. Diagnose
Describe concrete issues and their effects. Avoid vague diagnoses such as “it feels bland” without identifying the visual cause.

### 10. Revise
Fix the highest-impact issues first. Re-render and re-evaluate. If a clearly fixable material problem is found, perform at least one self-revision before treating the work as final.

## Boundaries
- Do not impose one fixed aesthetic taste on every product.
- Do not equate symmetry, simplicity, whitespace, or maximal usability with beauty by default.
- Do not remove intentional tension or friction merely to satisfy a generic UX convention.
- Do not copy reference designs.
- Do not fabricate brand facts.
- Do not use “intentional design” as a post-hoc excuse for an accidental problem.
