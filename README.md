# 잡이쓰 · 랜딩 + 첫 사용자 온보딩

랜딩에서 서비스를 이해하고, 그대로 온보딩으로 이어지는 한국어 커리어 탐색 서비스입니다.

`exp-07-lightweight-memory-v2`의 랜딩과 `exp-08-b-curated-memory`의 온보딩을 하나의 앱으로 합쳤습니다.

| 경로 | 화면 | 출처 |
| --- | --- | --- |
| `/` | 랜딩 — 히어로, 입력 맥락 바, 선택형 편지, 사용법, 경험 누적, FAQ | exp-07 |
| `/start` | 온보딩 — 관심 선택 → 경험 한 줄 → 직무 가능성 → 첫 커리어 편지 | exp-08-b |

랜딩의 모든 시작 CTA는 `/start`로 이동합니다. 라우팅은 History API 기반이며 별도 라우터 의존성은 없습니다.

## 실행

```sh
npm install
npm run dev
```

기본 주소는 `http://localhost:3000`입니다. 다른 서버가 사용 중이면 `PORT=3008 npm run dev`처럼 포트를 지정하세요.

```sh
npm test
npm run lint
npm run build
PORT=3009 npm start
```

## 구현 범위

### 랜딩 (`/`)

- 봉투 히어로와 이력서보다 넓은 입력 맥락 바
- 연결 출처(프로젝트·관심사·활동)를 고르면 내용이 바뀌는 편지 섹션
- 3단계 사용법, 경험 누적 설명, FAQ, 시작 CTA
- 편지는 **예시**로 명시하며, 사용자 상태를 저장하지 않습니다

### 온보딩 (`/start`)

- 8가지 관심 복수 선택, 선택에 반응하는 편지 미리보기
- 관심만 또는 경험만으로 분석 시작, 이름 선택 입력
- **대화 사이클** — 직무 가설마다 *내가 쓴 문장*(원문 인용)과 *AI가 읽은 내용*(해석)을 나눠 보여줌. 해석이 모호하면 확인 질문, "이 해석은 달라요"로 정정, 답변·정정에 따라 재분석. 근거가 부족하면 판단 보류
- 적합도 점수 없음. 원문에서 확인되지 않은 인용은 서버에서 버림 (`src/grounding.ts`)
- 체험 우편함, 개인화 연결 설명, 확인할 점, 다음 행동과 완료 표시
- 공고 저장·넘김·복원, 경험 추가와 재분석
- 버전이 있는 브라우저 임시 저장과 새로고침 복원
- 빈 입력 차단, 분석 중 중복 요청 방지, 45초 타임아웃, 실패 시 입력 유지와 재시도
- 반응형 화면, 키보드 포커스, 네이티브 모달, 모션 줄이기 대응

## 데이터 및 연결

실제 계정과 채용 데이터베이스는 연결되어 있지 않습니다. 첫 우편함은 기존 예시 기업과 직무 데이터를 활용한 **체험 공고**이며, 화면에서도 명시합니다. 실제 채용 지원·이메일 발송은 수행하지 않습니다.

### AI 분석 켜기

```sh
cp .env.example .env
```

`.env`의 `GEMINI_API_KEY`에 키를 넣고 서버를 재시작하세요. `.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다. 키를 `.env.example`이나 코드에 적지 마세요. 현재 모드는 `GET /api/health`의 `analysisMode`와 결과 화면 상단에서 확인할 수 있습니다.

키가 없으면 **체험 모드**로 동작합니다. 적어주신 문장을 근거로만 보여주고 의미는 해석하지 않으며, 직무 가설은 사용자가 직접 고른 관심에서만 만듭니다. 실제 Gemini 호출은 이 환경에서 검증하지 않았습니다. 검증 기록과 남은 한계는 [대화 사이클 검증](experiment-context/conversation-cycle-verification.md)에 있습니다.

이름, 경험, 결과, 대화 기록, 선택은 브라우저의 `jobiss.onboarding.v2` 키에 저장합니다. 분석 요청에는 경험, 관심, 대화 중 답변·정정만 보냅니다. 포트폴리오·GitHub 링크를 적을 수 있지만 링크 내용을 자동 수집하지는 않습니다. 도움말에서 이 브라우저의 입력을 초기화할 수 있습니다.

랜딩의 편지는 예시 데이터로 만든 데모이며 브라우저에 아무것도 쓰지 않습니다. 실제 상태는 `/start`에서만 만들어집니다.

## 스타일 구성

`src/styles.css`가 기준(reset, 디자인 토큰, 온보딩)이고, 랜딩 스타일은 `src/landing.css`에 `.landing` 스코프로 들어갑니다. 두 화면의 클래스 이름이 16개 겹쳐서 랜딩 쪽에는 `lp-` 접두사를 붙였습니다. 토큰은 랜딩 팔레트로 통일했습니다(`--ink: #20354b`, `--muted: #718090`, `--blue: #add6ff`).
