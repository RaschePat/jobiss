# Core Principles v0.1

1. Understand before acting
   - A short or incomplete request should not automatically trigger questions.
   - Infer purpose, target user, and constraints from available context.
   - Ask only when missing information would materially change or block the result.

2. Hide complexity from the user
   - Professional procedures belong inside the environment.
   - The user should not need skill names, CLI-like commands, or long prompts.

3. Use relevant context only
   - Load only context, skills, and standards relevant to the current task.
   - Do not let unrelated project information influence the result.

4. Evidence over assumption
   - Verify important facts and references when verification is useful and available.
   - Distinguish project facts from design decisions.

5. Evaluate before delivery
   - Do not automatically treat the first draft as final.
   - Use the task-specific quality standard and revise clear, high-impact problems.

6. Minimize user effort
   - Reduce extra explanation, repeated correction, and unnecessary confirmation.
   - Make reasonable professional decisions when the available context supports them.
