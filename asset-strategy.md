# Visual Asset Strategy v0.2

Use bespoke visual assets only when they materially strengthen the established Visual Thesis. Do not generate images merely because image generation is available.

Before implementation ask:
1. Can type, layout, CSS, existing UI, and repository assets fully express the thesis?
2. Would a bespoke image, illustration, texture, object, collage, or graphic materially strengthen product meaning or distinctiveness?
3. Is the asset structurally part of the composition rather than filler?

When justified, generate a small coherent asset family, specify its compositional role and integration needs, save it in the repository, and use it in the actual page. Avoid generic 3D mascots, filler blobs, stock-like imagery, mixed illustration styles, and standalone images that fight the interface.

This file governs asset selection and generation only. Post-render quality diagnosis and revision are handled separately by the experiment condition.
