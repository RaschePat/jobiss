# Design Learning Memory v0.1

## Purpose
This file stores observed user judgments from prior design evaluation. Treat these as evidence about preferences and decision criteria, not as a fixed style recipe. Apply only when relevant to the current task.

## Observed Judgments

### Visual direction
- The user strongly preferred the more editorial, graphic-system-driven landing-page direction over the friendlier conventional illustrated SaaS direction.
- The preferred result used large typography, a disciplined grid, document/paper language, annotations, strong scale contrast, and bespoke visual material to create a cleaner and more authored visual world.
- The user values a clean, sophisticated result, but `clean` alone is not sufficient; generic SaaS component assembly is not the target.

### Product storytelling
- The user judged the alternative design stronger at explaining how Jobiss moves beyond possibility/fit judgment into preparation and action.
- The line `합격 가능성보다 준비할 방법을 알려줘요.` was specifically valued because it communicates an important product principle: analysis should lead to what the user can do next.
- Preserve the progression from discovering possibilities to understanding evidence/gaps and then to concrete next actions. Visual sophistication should not weaken this progression.

### Mailbox / arrival metaphor
- The user still values the mailbox/arrival idea as a strong Jobiss product metaphor.
- In the preferred visual direction, the user wanted the `오늘 도착한 가능성을 열어보세요` area to make the arrival/mailbox experience more visible.
- Do not interpret this as a requirement to reuse a cartoon mailbox. Re-express the arrival metaphor in a way that belongs to the chosen visual world.

### Product mockups
- The user did not reject the mobile product mockup itself, but felt its placement weakened the preferred composition.
- Product UI should act as evidence of how Jobiss works, not automatically become the dominant visual device of a section. Reposition or reframe it when another product metaphor should lead the scene.

### Ending
- The user preferred the alternative design's final-page/ending treatment over the preferred design's ending.
- Treat the ending as a deliberate final composition rather than a generic centered CTA afterthought.

## Generalized Decision Principles
1. Prefer authored visual systems over familiar AI/SaaS assembly when product clarity can be preserved.
2. Art direction should amplify product meaning, not replace the product story.
3. For Jobiss, communicate not only `what fits me?` but also `why?`, `what is missing?`, and `what should I do next?`.
4. Reuse product metaphors conceptually, not by mechanically copying previous visual objects.
5. Use remembered judgments as constraints and priorities, not as instructions to recreate a previous page.

## Guardrails
- Do not mention this memory file to the user unless asked.
- Do not copy a previous layout or asset merely because it was preferred.
- Do not assume every future project should use editorial typography, documents, or mail metaphors; these observations are strongest for Jobiss and adjacent design tasks.
- When a remembered preference conflicts with the current explicit request or product context, the current request wins.
