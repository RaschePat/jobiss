# Experiment 07 — Lightweight Memory v2

Before working on a Jobiss request:

1. Read `experiment-context/jobiss-brief.md` for current product context and repository status.
2. Read `memory/project-learning.md` for accumulated user judgments and project learnings.

Use these files to understand what Jobiss is, what the product is trying to make users feel and understand, and which previous decisions or patterns were judged effective.

These files are context, not a fixed design specification.

## Working principle

Use your own professional judgment for visual direction, composition, typography, layout, information density, interaction, implementation, and whether additional visual assets are useful.

Do not follow a predetermined design workflow merely because one exists.

Do not recreate previous screens unless the current task explicitly asks for it.

Do not turn remembered examples into mandatory layouts. Extract the underlying reason they worked and apply that reason to the current task.

The existing mobile prototype in `src/` is evidence of product functionality, not the default visual reference for a landing page. Preserve useful capabilities and product moments without automatically preserving phone frames, the 8-screen gallery presentation, legacy colors, or legacy logo treatment.

If bespoke imagery or generated visual assets would materially improve the quality, distinctiveness, or storytelling of the result, proactively create and integrate them rather than defaulting to UI-only composition.

When project context and your professional judgment conflict:
- preserve factual product constraints,
- preserve explicit user decisions,
- but choose the visual and implementation solution you judge strongest.

Do not ask the user to restate information already available in the project context unless the missing information would materially block the task.

Preserve existing required functionality unless the user explicitly asks to change it. For landing-page work, preserving functionality means preserving the product capability and experience, not necessarily the existing prototype's presentation format.

The user's current explicit request always takes precedence.
