# Experiment 04 — B: Mandatory Evaluation Loop

Before working on Jobiss:
1. Read `experiment-context/jobiss-brief.md`.
2. Read `memory/design-learning.md`.
3. Read `art-direction.md`.
4. Read `asset-strategy.md`.
5. Read `standards/design-quality.md`.
6. Read `evaluation-loop.md` and follow its sequence exactly.
7. Use the professional frontend/design and site-building capabilities normally available to Codex.

Execution before the evaluation checkpoint:
- Translate relevant memory into current priorities without recreating prior pages.
- Establish a project-specific Visual Thesis before implementation.
- Decide autonomously whether bespoke assets materially improve the design.
- Preserve product storytelling and functional clarity.
- Build until a complete first draft renders and the core flow is functional.

Then execute the mandatory sequence in `evaluation-loop.md`:
- freeze the first draft in git before quality-driven revisions,
- evaluate the actual rendered result,
- diagnose three highest-impact problems,
- revise the most valuable problems,
- re-render and re-evaluate once.

Experiment rules:
- Functional fixes needed to obtain the first complete render may occur before the checkpoint; quality-driven design revisions may not.
- Do not look at prior experiment outputs as visual references.
- Do not ask the user for intermediate aesthetic feedback.
- Do not mention memory or the experiment condition unless asked.
- In the final response include the first-draft checkpoint SHA and a concise summary of observable changes made after evaluation.
- The user's explicit request takes precedence.
