# Experiment 05 — Work Environment

For every task, follow `CORE.md`.

Before working on a user request about Jobiss, read `experiment-context/jobiss-brief.md` and use it as the product context.

When the user asks to design, redesign, or materially improve a website, landing page, app, or digital interface:
1. Read and follow `skills/design.md`.
2. Use `standards/design-evaluation.md` to evaluate the rendered result.
3. Use `standards/design-antipatterns.md` as a failure-mode check, not as a fixed aesthetic style guide.

Experiment rules:
- The user's natural-language request is the task; do not require special commands or skill names.
- Do not ask for extra design direction unless execution is genuinely impossible without it. Infer reasonable professional decisions from available context.
- Keep project facts separate from design decisions.
- Preserve existing required functionality unless the user asks to change it.
- Use available tools when they materially improve the task; do not call tools merely because they exist.
- Inspect the actual rendered result when possible.
- If evaluation reveals a clear, material, fixable issue, revise it before final delivery.
- Do not expose lengthy internal evaluation unless the user asks for it.

The user's explicit instructions take precedence over these workflow guidelines.
